<objective>
Wire a real Strands **Supervisor** Agent to a **Gig Triage** specialist via the verified
agents-as-tools pattern (D-01), and expose Stage 1 end-to-end through FastAPI: `POST /capture`
(create record -> run triage via the DI seam -> merge the typed `TriageSlice` verbatim ->
persist -> return the verdict) and `GET /engagements/{id}` (read-through with 404). Because
Phase 2 is not built yet, the triage *logic* is a clearly-marked deterministic **placeholder**
(D-03/D-04) behind a stable `TriageRunner` seam that Phase 2 replaces without touching this
phase's Supervisor/API code. FastAPI stays the sole store writer (REC-03/D-05).

**User story** (derived faithfully from the ROADMAP Phase 3 Goal + PROJECT.md core value; not
in strict `As a / I want / so that` form in ROADMAP.md — reframed, not invented):
**As a** freelancer, **I want to** POST a structured job posting to the backend and get back a
triage verdict from a genuine Supervisor->specialist orchestration that is persisted as an
Engagement Record, **so that** Stage 1 is provably reachable end-to-end before the Chrome
extension (Phase 4) or the real triage tools (Phase 2) exist.

Purpose: Establish and prove the ORC-02 typed-pass-through mechanism (the most-judged
"genuine multi-agent orchestration" claim) on the smallest slice — one specialist — so every
later specialist drops into the same seam.
Output: `backend/api.py`, `backend/agents/{supervisor,gig_triage_agent,triage_runner}.py`,
`backend/tools/placeholder_triage.py`, five new test files, and the fastapi/uvicorn/httpx pins.

Delivers: **ORC-02** (typed JSON merged without Supervisor re-authoring), **API-01**
(`POST /capture`), **API-02** (`GET /engagements/{id}`).
